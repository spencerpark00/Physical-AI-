# D-008 로봇 시뮬레이션 (PyBullet)

> 엔진 오버홀 과정에서 **분해된 HPC 블레이드의 외관 검사 촬영**을 로봇이 수행하는 과정을
> PyBullet으로 재현한 시연 영상 제작 코드.

**현재 대표본: [`sim_blade_moby.py`](sim_blade_moby.py)** — Moby 이동 + 바닥 블레이드 4개 순차 검사

---

## 1. 이 영상이 증명하는 것

> **"1장은 사람이 빠르다. 하지만 엔진 1대에 블레이드는 수백 장이다."**

PM 문서(§5 프레임)를 그대로 따릅니다 — 싸울 곳은 *속도*가 아니라 **반복·일관성·기록**입니다.

| 근거 | 내용 |
| --- | --- |
| 물량 | 오버홀은 블레이드 **전수 검사**(입고 시 + 세척 후 2회). 대한항공 연 100대 → 360대 → 500대 목표 |
| 사람 성능 | 육안 검사 정확도 **오염 67% / 세척 87%**, 검사자 간 편차 큼 (Aust & Pons, 현업 50명) |
| 학술 결론 | 판정은 사람이 우수, 기술의 강점은 **일관성·가용성·무편향성** → 촬영은 기계, 판정은 사람 |
| 업계 선례 | 루프트한자 AutoInspect: 연소기 라이너 검사 4교대 → 4시간 미만 |

> ⚠️ **KPI 주의**: "검사 시간 단축"을 대표 지표로 걸면 위험합니다(1장당은 로봇이 느릴 수 있음).
> 증빙 완결률 · 검사자 간 편차 축소 · 판정 집중 시간 · 야간 일괄 처리량 쪽으로 거는 것이 이 논리와 정합합니다.

## 3. 씬과 동작 (sim_blade_moby.py)

```
검사 대상 블레이드 4개가 바닥 트레이에 일정 간격(62cm)으로 놓여 있다
        ↓
Moby(이동 베이스)가 다음 블레이드 앞으로 이동해 자리를 잡는다
        ↓
정지하면 Indy7이 팔을 내려 블레이드 바로 위 42cm에서 수직으로 내려다보며 촬영
        ↓
팔을 접고 다음 블레이드로 — 4개 반복
```

| 구간 | 시간(1.5배속) | 내용 |
| --- | --- | --- |
| drive | 1.07s | Moby 이동 |
| reach | 0.60s | 팔 내리기 |
| **hold** | 0.33s | **정지 = 촬영** (플래시 +15%) |
| back | 0.47s | 팔 접기 |

**색으로 보는 진행 상황**
- 회색 = 검사 대기
- **청록 = 지금 촬영 중**
- 초록 = 검사 완료

> 뒷면 검사는 하지 않습니다 — **바닥에 놓인 그대로** 위에서 촬영.

## 5. 삽질 기록 — 같은 문제를 다시 만나면

### ① IK가 목표 x를 10cm 빗나감 → 카메라가 블레이드 중앙을 못 잡음
PyBullet IK는 자세(orientation) 제약이 걸리면 위치 잔차를 남깁니다. 목표 좌표를 손으로 밀어 보정하면
블레이드를 옮길 때마다 카메라도 따라와 계속 어긋났습니다. **런타임 반복 보정**으로 해결:

```python
def solve_shoot():
    q = ik_at(tx, ty, tz)
    for _ in range(6):
        pos = p.getLinkState(robot, EE)[4]
        ex, ey = pos[0] - 0.0, pos[1] - BLADE_Y
        if abs(ex) < 0.003 and abs(ey) < 0.003: break
        tx -= ex; ty -= ey        # 잔차만큼 목표를 되밀어 재수렴
        q = ik_at(tx, ty, tz)
    return q
```
→ 오차 **10cm → 3mm**, 4개 블레이드 전부 동일 조건.

### ② "정지 자세만 검사하면 이동 중 관통을 놓친다"
자세 4개만 확인하고 통과했다고 판단했는데, 관절 직선 보간 구간에서 팔이 구조물을 **10cm 통과**했습니다.
이후로는 **전 프레임 전수 검사**를 기본으로 합니다.

```python
for f in range(int(DUR*FPS)):
    apply_state(f/FPS); p.performCollisionDetection()
    for b in BLADES + TRAY:
        for cp in p.getContactPoints(robot, b):
            if cp[8] < -0.005: bad += 1
```

### ③ "싱크가 안 맞아 보인다"가 실제로는 색 문제였음
좌표상으로는 정확했는데(SHOT0→#0 … SHOT3→#3, 오차 3mm), 초록색이 *촬영 중*이 아니라
*이미 끝난* 블레이드라 로봇이 엉뚱한 걸 찍는 것처럼 보였습니다 → **촬영 중(청록) 색 추가**로 해결.

### ④ 영상이 재생되지 않음
H.264 **High** 프로파일이 일부 플레이어에서 막힙니다 → **Constrained Baseline + yuv420p + faststart**로 재인코딩.

### ⑤ 콘솔 인코딩(cp949)
`—`(em dash), `→` 같은 문자를 `print`하면 Windows 한글 콘솔에서 `UnicodeEncodeError`로 죽습니다. ASCII로 대체.
