# D-008 PyBullet 블레이드 검사 시뮬레이션

> 엔진 오버홀 중 분해된 **HPC 블레이드**를 로봇이 3면 촬영하고,
> 품질 미달 시 파라미터를 보정해 재촬영하는 과정을 재현한 23초 루프 영상.

**증명하는 것**
> "로봇이 블레이드 한 개를 **같은 조건(각도·거리·조명)으로 3면 촬영**하고,
> 품질이 미달하면 **파라미터를 보정해 다시 찍는다**."

D-008 서사와 직결 — 사람이 찍으면 매번 달라지는 것을 로봇은 **똑같이 반복**한다.

---

## 실행

```bash
cd C:\Users\User\robotsim

py -3.11 sim_blade.py            # 3D 창 미리보기 (마우스로 시점 회전)
py -3.11 sim_blade.py --render   # 오프스크린 렌더 -> frames/*.png
py -3.11 make_mp4.py             # PNG -> sim.mp4
```

데모 연동 (파일만 넣으면 끝, 코드 수정 불필요):
```bash
copy sim.mp4 "...\서비스\assets\sim.mp4"
```
→ 정비사 앱 **로봇 촬영 모달** + **로봇 HUD**에서 자동 재생 (없으면 정지 이미지 폴백)

**필요 환경**: Python 3.11 · `pybullet` (conda-forge) · `numpy` · `imageio-ffmpeg`
> pybullet은 Python 3.14에 사전빌드 wheel이 없어 3.11 + conda 설치 사용.
> ffmpeg 별도 설치 불필요 — `imageio-ffmpeg` 내장 바이너리 사용.

## 타임라인 (23초 루프)

| 구간 | 시간 | 동작 |
| --- | --- | --- |
| A 대기 | 0–2s | 홈 포즈 (루프 시작·종료 동일) |
| B 접근 | 2–5s | 리딩엣지 포즈로 |
| C 촬영 1 | 5–7s | 정지 + 플래시 |
| D 이동 | 7–10s | 압력면으로 |
| E 촬영 2 | 10–12s | 정지 + 플래시 |

| G 촬영 3 | 15–17s | 정지 + 플래시 |

## 씬 구성

| 요소 | 사양 |
| --- | --- |
| 바닥 | 어두운 회색 (데모 UI 톤) |
| 검사 스탠드 | 얇은 상판(24×24cm) + 가는 다리 4개 |
| 거치 포스트·바이스 | 블레이드를 상판 위 22cm에 거치 |
| HPC 블레이드 | Sketchfab HPT Blade, 실제 높이 **21.9cm** |
| 로봇 | **Indy7** (뉴로메카 URDF), 페데스탈(62cm) 위 |
| 카메라 헤드 | 플랜지에 부착된 박스+렌즈 (IndyEye 상징) |

> **스케일 주의**: 실제 HPC 블레이드는 수 cm이지만 **화면 가시성을 위해 20~25cm급으로 확대**했습니다.
> 수치 정밀 재현이 목적이 아니며, "흐름 가시화를 위한 연출 스케일"입니다.

## 구현 원칙 (시나리오 문서 준수)

**한 것**
- 관절 **키프레임 + ease-in-out 보간** (물리 시뮬 불필요)
- 각 촬영 포즈는 **블레이드 중심을 바라보도록** 방향 지정
- 촬영 순간 0.2초 **밝기 +15% 플래시**
- 메인 카메라 3인칭 고정, yaw 10° 서행

**안 한 것 (범위 가드)**
- 영상 내 **자막·라벨·bbox 없음** — 데모 HTML이 오버레이 담당
- 정밀 물리·중력 낙하·실시간 IK 풀이
- 그리퍼·공구 파지 (D-007 범위 밖), Moby 주행, 사람 모델

**경유 자세(waypoint)**: 자세 사이를 직선 보간하면 팔이 고정구·스탠드를 통과하므로,
블레이드보다 30cm 위로 우회하는 중간 자세 3개를 넣었습니다 (실제 로봇의 이동 방식과도 유사).

**검증**: **690프레임 전수 검사** — 정지 자세뿐 아니라 **이동 중 프레임까지 구조물 관통 0건**
> 정지 자세만 검사하면 이동 경로의 관통을 놓칩니다(실제로 13~14초 구간에서 고정구를 10cm 통과했음).
